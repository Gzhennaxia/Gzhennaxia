# 个人记账系统 — 需求说明

> 归属 Gzhennaxia「人生管理」模块，与任务、金融监控等并列扩展。静态原型位于 `prototype/accounting/`。

## 1. 产品定位

面向**单人**的收支与投资记录工具：不追求企业财务复杂度，强调**快速记一笔、看清钱花哪、投资赚多少**。

| 模块 | 目标 |
|------|------|
| 消费记账 | 日常支出/收入流水、分类、多账户、预算与月报 |
| 投资记账 | 持仓、买卖/分红流水、成本与浮动盈亏、资产占比 |
| 总览 | 净资产、本月收支、投资市值与储蓄率 |

## 3. 核心实体（数据模型草案）

> 各业务表统一使用 `create_time`、`update_time`（DATETIME）作为创建/更新时间；下文未单独列出的表亦遵循此约定。

### 3.1 资金账户 `fund_account`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| name | VARCHAR(50) | 账户名称，如「招行工资卡」 |
| account_no | VARCHAR(64) | 账户编号，可选；存银行卡号、支付宝账号 ID、券商资金账号等，展示时需脱敏 |
| type | VARCHAR(20) | 枚举：bank / alipay / wechat / cash / credit / virtual / other；`virtual` 用于人情往来、报销垫款等仅记账账户 |
| currency | VARCHAR(3) | 默认 CNY |
| balance | DECIMAL(14,2) | 当前余额（可通过对账校正） |
| include_in_net_worth | TINYINT | 是否计入净资产：1=计入，0=不计入。信用卡负债、人情往来等虚拟账户通常为 0，避免净资产失真 |
| sort_order | INT | 排序 |
| remark | TEXT | 备注 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

## 4. 功能需求摘要

### 4.1 消费记账

1. **记一笔**：支出 / 收入 / 账户间转账；默认时间为当前，可改。
2. **分类**：系统预设 + 用户自定义二级分类；支持月预算。
3. **多账户**：每笔绑定一个账户；转账双账户联动。
4. **虚拟账户**（规划）：如人情往来、报销垫款等，`type=virtual` 且 `include_in_net_worth=0`，只记谁欠谁、不影响首页净资产。
5. **流水**：按日期、类型、分类、账户、关键词筛选；支持导出 CSV。
6. **周期账单**（二期）：水电、订阅等模板，到期提醒。

### 4.2 投资记账

1. **手动录入**买卖、分红、申赎；暂不对接券商自动同步（可与 IBKR 模块后续打通）。
2. **持仓**：展示数量、成本价、现价（可选接行情 API）、浮盈浮亏、占比。
3. **资产分布**：按市场、品种饼图。
4. **与消费分离**：投资账户资金变动可通过「转账到券商」与消费账联动。

### 4.3 报表

1. **月报**：收入、支出、结余、分类 Top、同比环比。
2. **储蓄率**：(收入 - 支出) / 收入。
3. **预算**：分类超支标红。

## 5. 非功能需求

- 单用户，无需多租户；与 Gzhennaxia 统一 JWT / 登录（实现阶段）。
- 金额 `DECIMAL`，展示保留 2 位；多币种二期。
- 响应式：PC 为主，手机可记一笔（与现有 `Mobile` 路由风格一致）。
- 敏感数据本地 H2/SQLite，不上传第三方。

## 6. 与现有仓库的关系

| 现有能力 | 关系 |
|----------|------|
| `financial-service` 股票监控 | 可提供现价；投资持仓展示可复用行情缓存 |
| `docs/IBKR` | 未来可做 IB 成交导入 |
| `frontend/Finance` | 实现阶段可新增「记账」子路由或独立 `Accounting` 模块 |

## 7. 技术栈建议（实现阶段）

- 后端：新建 `accounting-service` 或并入 `financial-service` 子域，Spring Boot + MyBatis-Plus + H2。
- 前端：React + Ant Design，与 `frontend` 一致。
- 图表：ECharts（原型已用 CDN 演示）。
