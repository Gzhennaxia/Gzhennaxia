pojo

1. request, 用于接收前端传参，只能在controller，不可跨层
2. dto，用于各层直接的跨层
3. entity，实体类，字段对应表结构的字段
4. vo，用于返回前端，同request，只能在controller，不可跨层

对于一个接口，会从 request，到 dto，再到entity，再到 vo，再到前端

Spring Boot + mybatis plus + H2 如何配置，避免表明列明都是大写，与实体类的映射问题

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:testdb;AUTO_SERVER=TRUE;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE;MODE=MySQL;DEFAULT_NULL_ORDERING=LOW
    driver-class-name: org.h2.Driver
    username: sa
    password:
```
AUTO_SERVER=TRUE

作用：允许 H2 数据库文件被多个进程安全访问。

默认情况下，H2 文件数据库（比如 jdbc:h2:~/test）只能单进程独占使用。

配置了 AUTO_SERVER=TRUE 后，H2 会在后台启动一个小型 TCP 服务器，当有其他 JVM 进程也连接同一个数据库文件时，它们会通过这个 TCP 通道共享访问。


🔹 DB_CLOSE_DELAY=-1

作用：控制 H2 内存数据库的生命周期。

默认行为：H2 的 内存数据库（jdbc:h2:mem:testdb） 会在 最后一个连接关闭后立刻销毁。

配置了 DB_CLOSE_DELAY=-1 后，即使所有连接都关闭，数据库也会 一直保存在 JVM 内存中，直到 JVM 退出。

👉 使用场景：

在 Spring Boot 测试环境中，应用启动时建表、插数据，后面如果 DataSource 关闭再重连，不会丢表/丢数据。



DEFAULT_NULL_ORDERING=HIGH

这个参数是 H2 数据库的排序配置，控制 ORDER BY 时 NULL 值的位置。

不同数据库对 NULL 在排序时的位置有不同的默认规则：

Oracle：ORDER BY ASC 时，NULL 默认排在最后；ORDER BY DESC 时，NULL 默认排在最前。

PostgreSQL：可以显式指定 NULLS FIRST 或 NULLS LAST。

MySQL：NULL 在升序中排在最前，在降序中排在最后。

H2 默认的规则可能和目标数据库不一样，所以它提供了 DEFAULT_NULL_ORDERING 来统一行为。
