# 🔧 后端规范

## 🏗️ POJO 分层规范

### 分层定义

| 层级 | 类型 | 用途 | 使用范围 | 说明 |
|------|------|------|----------|------|
| **Request** | 请求对象 | 接收前端传参 | 仅限Controller层 | 不可跨层使用 |
| **DTO** | 数据传输对象 | 各层之间数据传输 | 跨层使用 | 业务逻辑层间传输 |
| **Entity** | 实体类 | 数据库映射 | 持久层 | 字段对应表结构 |
| **VO** | 视图对象 | 返回前端数据 | 仅限Controller层 | 不可跨层使用 |

### 数据流转路径
```
前端 → Request → DTO → Entity → DTO → VO → 前端
```

## 🌐 API 接口规范

### 分页请求格式 (PageRequest)

```json
{
  "pageNo": 1,
  "pageSize": 10,
  "query": {
    "id": 123,
    "type_like": "EAD",
    "createTime_lte": "2025-08-28 18:32:26",
    "createTime_gte": "2025-08-28 18:32:26"
  },
  "sort": {
    "createTime": "desc"
  }
}
```

#### 查询条件说明
- `字段名_like`: 模糊查询
- `字段名_lte`: 小于等于
- `字段名_gte`: 大于等于

### 统一响应格式 (Response)

```json
{
  "status": 200,
  "message": "success",
  "data": {
    // 具体数据内容
  }
}
```

#### 响应处理机制
- 通过**全局拦截器**自动封装所有接口返回结果
- 包括正常响应和异常响应的统一处理
- 避免手动重复编码

## 🗄️ 数据库规范

### 表结构设计规范

#### ID字段规范
- **数据库字段**: 统一使用 `BIGINT` 类型
- **实体类字段**: 对应使用 `Long` 类型
- **目的**: 确保足够的数值范围，支持大数据量场景

### 标准字段
**每个表都必须包含以下标准字段：**

```sql
CREATE TABLE IF NOT EXISTS table_name (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键，统一使用BIGINT类型',
  status       INTEGER NOT NULL DEFAULT 1 COMMENT '状态：1=启用，0=禁用',
  deleted      INTEGER NOT NULL DEFAULT 0 COMMENT '删除标记：0=未删除，1=已删除',
  remark       TEXT COMMENT '备注信息',
  created_time DATETIME         DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_time DATETIME         DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间'
);
```

#### 字段说明
| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `id` | BIGINT | 自增 | 主键，统一使用BIGINT类型 |
| `status` | INTEGER | 1 | 状态：1=启用，0=禁用 |
| `deleted` | INTEGER | 0 | 删除标记：0=未删除，1=已删除 |
| `remark` | TEXT | NULL | 备注信息 |
| `created_time` | DATETIME | 当前时间 | 创建时间 |
| `updated_time` | DATETIME | 当前时间 | 更新时间 |

### 索引设计规范

#### 唯一索引规范
> **重要：创建唯一索引时，必须包含软删除字段 `deleted`**

**✅ 正确示例：**
```sql
-- 用户邮箱唯一索引（包含deleted字段）
CREATE UNIQUE INDEX uk_user_email ON user_info(email, deleted);

-- 字典编码唯一索引（包含deleted字段）
CREATE UNIQUE INDEX uk_dict_code ON dict(dict_code, deleted);

-- 组合字段唯一索引（包含deleted字段）
CREATE UNIQUE INDEX uk_user_phone ON user_info(phone, area_code, deleted);
```

**❌ 错误示例：**
```sql
-- ❌ 缺少deleted字段，会导致软删除后无法重新使用相同值
CREATE UNIQUE INDEX uk_user_email ON user_info(email);
CREATE UNIQUE INDEX uk_dict_code ON dict(dict_code);
```

#### 规范说明
- **目的**: 确保软删除的记录不会影响新记录的唯一性约束
- **效果**: 同一个邮箱/编码在软删除后可以重新使用
- **原理**: 数据库会将 `(email='test@example.com', deleted=0)` 和 `(email='test@example.com', deleted=1)` 视为不同的记录
- **适用范围**: 所有需要唯一性约束的业务字段

## ⚙️ H2 数据库配置

### Spring Boot 配置

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:testdb;AUTO_SERVER=TRUE;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE;MODE=MySQL;DEFAULT_NULL_ORDERING=LOW
    driver-class-name: org.h2.Driver
    username: sa
    password:
```

### 配置参数详解

#### 🔹 AUTO_SERVER=TRUE
- **作用**: 允许H2数据库文件被多个进程安全访问
- **原理**: H2在后台启动TCP服务器，多个JVM进程通过TCP通道共享访问
- **场景**: 避免单进程独占数据库文件的限制

#### 🔹 DB_CLOSE_DELAY=-1
- **作用**: 控制H2内存数据库的生命周期
- **效果**: 即使所有连接关闭，数据库也保存在JVM内存中直到JVM退出
- **场景**: Spring Boot测试环境中，避免DataSource重连时丢失表和数据

#### 🔹 DATABASE_TO_LOWER=TRUE
- **作用**: 避免表名和列名大写问题
- **效果**: 与实体类映射时保持一致的命名规范

#### 🔹 MODE=MySQL
- **作用**: 设置H2兼容MySQL语法模式
- **效果**: 支持MySQL特有的SQL语法和函数

#### 🔹 DEFAULT_NULL_ORDERING=LOW
- **作用**: 控制ORDER BY时NULL值的排序位置
- **效果**: NULL值在升序时排在最前，降序时排在最后
- **说明**: 统一不同数据库的NULL排序行为

### 数据库NULL排序对比

| 数据库 | 升序(ASC) | 降序(DESC) |
|--------|-----------|------------|
| **Oracle** | NULL在最后 | NULL在最前 |
| **MySQL** | NULL在最前 | NULL在最后 |
| **PostgreSQL** | 可指定NULLS FIRST/LAST | 可指定NULLS FIRST/LAST |
| **H2(配置后)** | NULL在最前 | NULL在最后 |

# 🎨 前端规范

## 🎯 样式规范

### 核心原则
> **禁止定义全局样式，必须使用局部样式**

### 样式实现方式

#### ✅ 推荐方式

**1. 内联样式 (Inline Styles)**
```tsx
// ✅ 推荐：组件内部使用内联样式
const MyComponent = () => {
  return (
    <div style={{ margin: '5px 5px 5px 0', padding: '10px' }}>
      <Form.Item style={{ marginBottom: '16px' }}>
        <Input style={{ height: '32px' }} />
      </Form.Item>
    </div>
  );
};
```

**2. CSS Modules**
```tsx
// ✅ 推荐：使用CSS Modules
import styles from './MyComponent.module.css';

const MyComponent = () => {
  return (
    <div className={styles.container}>
      <Form.Item className={styles.formItem}>
        <Input className={styles.input} />
      </Form.Item>
    </div>
  );
};
```

**3. Styled Components**
```tsx
// ✅ 推荐：使用styled-components
import styled from 'styled-components';

const Container = styled.div`
  margin: 5px 5px 5px 0;
  padding: 10px;
`;

const StyledFormItem = styled(Form.Item)`
  margin-bottom: 16px;
`;
```

#### ❌ 禁止方式

**1. 全局CSS文件修改**
```css
/* ❌ 禁止：在全局CSS中覆盖Ant Design样式 */
.ant-input {
  height: 40px !important;
}

.ant-form-item {
  margin-bottom: 20px !important;
}
```

**2. 全局样式覆盖**
```css
/* ❌ 禁止：全局覆盖第三方组件样式 */
* {
  box-sizing: border-box !important;
}

body .ant-btn {
  border-radius: 8px !important;
}
```

### 样式命名规范

#### CSS Modules 命名
```css
/* MyComponent.module.css */
.container {
  display: flex;
  flex-direction: column;
}

.formItem {
  margin: 5px 5px 5px 0;
}

.searchInput {
  width: 200px;
  height: 32px;
}

/* 使用BEM命名法 */
.dictList__header {
  padding: 16px;
}

.dictList__searchForm {
  margin-bottom: 16px;
}

.dictList__table {
  background: white;
}
```

#### 内联样式对象
```tsx
// 定义样式对象，便于复用
const styles = {
  formItem: {
    margin: '5px 5px 5px 0',
  },
  input: {
    height: '32px',
  },
  container: {
    padding: '24px',
    background: '#fff',
  },
} as const;

const MyComponent = () => {
  return (
    <div style={styles.container}>
      <Form.Item style={styles.formItem}>
        <Input style={styles.input} />
      </Form.Item>
    </div>
  );
};
```

## 📝 后端注意事项

1. **严格遵循分层规范**: Request/VO仅限Controller层使用
2. **统一响应格式**: 所有API接口必须使用统一的响应体结构
3. **标准字段必备**: 新建表时必须包含所有标准字段
4. **H2配置完整**: 确保所有配置参数都正确设置，避免映射问题

## 📝 前端注意事项

1. **样式隔离**: 严禁修改全局样式，必须使用局部样式
2. **组件独立**: 每个组件都应该有自己的样式文件
3. **类型安全**: 使用TypeScript严格模式，确保类型安全
4. **性能优化**: 合理使用React.memo、useCallback、useMemo
5. **代码复用**: 提取公共组件和工具函数
