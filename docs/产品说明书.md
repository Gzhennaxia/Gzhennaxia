📅 "今天的任务"的定义
基于前端代码中的逻辑（TickTickMobile.tsx第172-190行），一个任务被认为是"今天的任务"需要满足以下条件：

✅ 核心判断条件：
任务状态条件：

status === 0 (待办) 或 status === 1 (进行中)
已完成(2)和已取消(3)的任务不算今天的任务
时间重叠条件（满足任一条件即可）：

条件1：任务开始时间在今天内

startTime >= 今天00:00:00 && startTime <= 今天23:59:59
条件2：任务结束时间在今天内

endTime >= 今天00:00:00 && endTime <= 今天23:59:59
条件3：任务跨越今天

startTime < 今天00:00:00 && endTime > 今天23:59:59
🎯 具体场景举例：
假设今天是 2025-09-08：

✅ 算作今天的任务：
今天开始的任务：

startTime: 2025-09-08 09:00:00
endTime: 2025-09-08 18:00:00
今天结束的任务：

startTime: 2025-09-07 20:00:00
endTime: 2025-09-08 10:00:00
跨越今天的长期任务：

startTime: 2025-09-07 00:00:00
endTime: 2025-09-10 23:59:59
今天开始的未来任务：

startTime: 2025-09-08 14:00:00
endTime: 2025-09-09 10:00:00
❌ 不算今天的任务：
昨天已结束的任务：

startTime: 2025-09-07 09:00:00
endTime: 2025-09-07 18:00:00
明天才开始的任务：

startTime: 2025-09-09 09:00:00
endTime: 2025-09-09 18:00:00
已完成的任务（无论时间）：

status: 2 (已完成)
💡 设计理念：
这种设计的优点是：

灵活性：支持跨天任务
实用性：今天需要处理的任务都会显示
直观性：用户能看到所有与今天相关的未完成任务
🤔 可能的优化建议：
如果你觉得当前逻辑不够符合需求，可以考虑：

仅按开始时间判断：只有今天开始的任务才算今天的任务
添加全天任务特殊处理：isAllDay=true 的任务按日期而非时间判断
添加优先级权重：高优先级任务可以提前显示
