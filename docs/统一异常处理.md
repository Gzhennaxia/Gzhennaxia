在 Spring Boot 项目中统一返回格式，是规范接口设计、降低前后端协作成本的核心手段。核心思路是：**定义统一的响应体结构**，并通过 **全局拦截/处理机制** 自动封装所有接口的返回结果（包括正常响应和异常响应），避免手动重复编码。


### 一、第一步：定义统一的响应体结构
首先需要设计一个通用的响应类（如 `ApiResponse`），包含所有接口返回的固定字段，确保格式一致性。通常需包含以下核心字段：

| 字段名       | 类型       | 说明                                                                 |
|--------------|------------|----------------------------------------------------------------------|
| `code`       | 整数/枚举  | 状态码（成功用 `200`，失败用自定义错误码，如 `400` 参数错误、`500` 服务器错误） |
| `message`    | 字符串     | 描述信息（成功时为 "success"，失败时为具体错误原因）                 |
| `data`       | 泛型（T）  | 业务数据（成功时返回具体数据，失败时可设为 `null`）                 |
| `timestamp`  | 长整数     | 响应时间戳（毫秒级，方便排查问题）                                   |

```json
{
    "code": 200,
    "message": "success",
    "data": {},
    "timestamp": "2025-09-03T14:22:06.847664300"
}
```

#### 1.1 定义状态码枚举（可选，推荐）

为了规范错误码管理，建议用枚举定义状态码和对应描述，避免硬编码：
```java
public enum ResponseCode {
    // 成功状态
    SUCCESS(200, "success"),
    // 客户端错误
    BAD_REQUEST(400, "参数错误"),
    UNAUTHORIZED(401, "未登录"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    // 服务器错误
    INTERNAL_ERROR(500, "服务器内部错误");

    private final int code;
    private final String message;

    ResponseCode(int code, String message) {
        this.code = code;
        this.message = message;
    }

    // Getter 方法
    public int getCode() { return code; }
    public String getMessage() { return message; }
}
```


#### 1.2 定义统一响应体类
使用泛型支持不同类型的业务数据，同时提供静态工厂方法简化封装：
```java
import lombok.Data;

import java.util.Date;

@Data // Lombok 注解，自动生成 Getter/Setter/toString 等
public class ApiResponse<T> {
    // 状态码（来自 ResponseCode 枚举）
    private int code;
    // 描述信息
    private String message;
    // 业务数据（泛型，支持任意类型）
    private T data;
    // 响应时间戳（毫秒）
    private long timestamp;

    // 私有构造，避免外部直接 new，通过工厂方法创建
    private ApiResponse(int code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
        this.timestamp = new Date().getTime(); // 自动填充时间戳
    }

    // ------------------- 静态工厂方法（简化调用） -------------------
    /**
     * 成功响应（无业务数据）
     */
    public static <T> ApiResponse<T> success() {
        return new ApiResponse<>(ResponseCode.SUCCESS.getCode(), ResponseCode.SUCCESS.getMessage(), null);
    }

    /**
     * 成功响应（带业务数据）
     */
    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(ResponseCode.SUCCESS.getCode(), ResponseCode.SUCCESS.getMessage(), data);
    }

    /**
     * 失败响应（用预定义的错误码）
     */
    public static <T> ApiResponse<T> fail(ResponseCode responseCode) {
        return new ApiResponse<>(responseCode.getCode(), responseCode.getMessage(), null);
    }

    /**
     * 失败响应（自定义错误信息）
     */
    public static <T> ApiResponse<T> fail(ResponseCode responseCode, String customMessage) {
        return new ApiResponse<>(responseCode.getCode(), customMessage, null);
    }

    /**
     * 失败响应（完全自定义错误码和信息，用于特殊场景）
     */
    public static <T> ApiResponse<T> fail(int customCode, String customMessage) {
        return new ApiResponse<>(customCode, customMessage, null);
    }
}
```


### 二、第二步：统一处理正常响应（避免手动封装）
如果每个接口都手动调用 `ApiResponse.success(data)`，会存在重复代码。通过 **`@RestControllerAdvice` + `ResponseBodyAdvice`** 可以全局拦截所有 `@ResponseBody` 注解的返回值，自动封装为统一格式。


#### 实现 ResponseBodyAdvice 拦截正常响应
```java
import org.springframework.core.MethodParameter;
import org.springframework.http.MediaType;
import org.springframework.http.converter.HttpMessageConverter;
import org.springframework.http.server.ServerHttpRequest;
import org.springframework.http.server.ServerHttpResponse;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.servlet.mvc.method.annotation.ResponseBodyAdvice;

/**
 * 全局响应体拦截器：自动将所有正常响应封装为 ApiResponse 格式
 */
@RestControllerAdvice(basePackages = "com.yourproject.controller") // 只拦截指定包下的控制器（避免拦截第三方接口）
public class GlobalResponseAdvice implements ResponseBodyAdvice<Object> {

    /**
     * 是否需要拦截：返回 true 表示拦截，进入 beforeBodyWrite 处理
     */
    @Override
    public boolean supports(MethodParameter returnType, Class<? extends HttpMessageConverter<?>> converterType) {
        // 排除本身就是 ApiResponse 的情况（避免重复封装）
        return !returnType.getParameterType().isAssignableFrom(ApiResponse.class);
    }

    /**
     * 拦截后的处理：将原始返回值封装为 ApiResponse
     */
    @Override
    public Object beforeBodyWrite(
            Object body, // 控制器方法的原始返回值
            MethodParameter returnType,
            MediaType selectedContentType,
            Class<? extends HttpMessageConverter<?>> selectedConverterType,
            ServerHttpRequest request,
            ServerHttpResponse response) {

        // 1. 处理 String 类型（特殊：Spring 默认用 StringHttpMessageConverter，直接返回 ApiResponse 会转成 JSON 字符串，需手动处理）
        if (body instanceof String) {
            // 这里需要引入 Jackson 依赖，将 ApiResponse 转为 JSON 字符串
            try {
                return new ObjectMapper().writeValueAsString(ApiResponse.success(body));
            } catch (JsonProcessingException e) {
                throw new RuntimeException("String 类型响应封装失败", e);
            }
        }

        // 2. 处理其他类型（直接封装为成功响应）
        return ApiResponse.success(body);
    }
}
```


#### 依赖说明（String 类型处理需 Jackson）
如果项目中没有引入 Jackson，需在 `pom.xml`（Maven）或 `build.gradle`（Gradle）中添加依赖：
```xml
<!-- Maven：Jackson（Spring Boot Web 已默认包含，一般无需额外引入） -->
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
</dependency>
```


### 三、第三步：统一处理异常响应（避免分散 try-catch）
接口抛出的异常（如参数错误、业务异常、系统异常）也需要封装为统一格式。通过 **`@RestControllerAdvice` + `@ExceptionHandler`** 全局捕获异常，自动转为 `ApiResponse`。


#### 3.1 定义自定义业务异常（可选，推荐）
业务中主动抛出的异常（如“用户不存在”“余额不足”），建议自定义异常类，方便区分异常类型：
```java
/**
 * 自定义业务异常：用于业务逻辑错误（如参数校验失败、资源不存在等）
 */
public class BusinessException extends RuntimeException {
    private final ResponseCode responseCode; // 错误码
    private final String customMessage;      // 自定义错误信息（可选）

    // 构造方法1：用预定义的错误码
    public BusinessException(ResponseCode responseCode) {
        super(responseCode.getMessage());
        this.responseCode = responseCode;
        this.customMessage = responseCode.getMessage();
    }

    // 构造方法2：自定义错误信息
    public BusinessException(ResponseCode responseCode, String customMessage) {
        super(customMessage);
        this.responseCode = responseCode;
        this.customMessage = customMessage;
    }

    // Getter 方法
    public ResponseCode getResponseCode() { return responseCode; }
    public String getCustomMessage() { return customMessage; }
}
```


#### 3.2 实现全局异常处理器
```java
import org.springframework.http.HttpStatus;
import org.springframework.validation.BindingResult;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.servlet.NoHandlerFoundException;

/**
 * 全局异常处理器：捕获所有异常，封装为统一的 ApiResponse 格式
 */
@RestControllerAdvice(basePackages = "com.yourproject.controller") // 只处理指定包下的异常
public class GlobalExceptionHandler {

    /**
     * 1. 处理自定义业务异常（BusinessException）
     */
    @ExceptionHandler(BusinessException.class)
    public ApiResponse<Void> handleBusinessException(BusinessException e) {
        // 返回自定义的错误码和信息
        return ApiResponse.fail(e.getResponseCode(), e.getCustomMessage());
    }

    /**
     * 2. 处理参数校验异常（@Valid 注解触发，如 @NotNull、@Size 等）
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValidException(MethodArgumentNotValidException e) {
        BindingResult bindingResult = e.getBindingResult();
        // 拼接所有参数错误信息（如："username: 不能为空; password: 长度不能小于6"）
        StringBuilder errorMsg = new StringBuilder();
        for (FieldError fieldError : bindingResult.getFieldErrors()) {
            errorMsg.append(fieldError.getField()).append(": ").append(fieldError.getDefaultMessage()).append("; ");
        }
        // 返回 400 错误码 + 拼接的错误信息
        return ApiResponse.fail(ResponseCode.BAD_REQUEST, errorMsg.toString().trim());
    }

    /**
     * 3. 处理 404 异常（资源未找到）
     */
    @ExceptionHandler(NoHandlerFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND) // 设置 HTTP 状态码为 404（可选，前端可通过状态码快速判断）
    public ApiResponse<Void> handleNoHandlerFoundException(NoHandlerFoundException e) {
        return ApiResponse.fail(ResponseCode.NOT_FOUND);
    }

    /**
     * 4. 处理其他未捕获的异常（兜底，如空指针、IO异常等）
     */
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR) // 设置 HTTP 状态码为 500
    public ApiResponse<Void> handleOtherException(Exception e) {
        // 生产环境建议记录日志（避免暴露敏感信息），这里简化处理
        e.printStackTrace();
        return ApiResponse.fail(ResponseCode.INTERNAL_ERROR, "服务器内部错误，请联系管理员");
    }
}
```


### 四、第四步：使用示例（控制器无需关注封装）
配置完成后，控制器方法可以直接返回原始业务数据，异常直接抛出，全局拦截器会自动处理统一格式。


#### 4.1 正常响应示例
```java
@RestController
@RequestMapping("/user")
public class UserController {

    @Autowired
    private UserService userService;

    // 1. 返回单个对象
    @GetMapping("/{id}")
    public User getUserById(@PathVariable Long id) {
        User user = userService.getById(id);
        if (user == null) {
            // 主动抛出业务异常，全局异常处理器会封装为统一格式
            throw new BusinessException(ResponseCode.NOT_FOUND, "用户不存在（ID：" + id + "）");
        }
        return user; // 正常返回 User 对象，全局响应拦截器会自动封装为 ApiResponse
    }

    // 2. 返回集合
    @GetMapping("/list")
    public List<User> getUserList() {
        return userService.list(); // 自动封装为 {"code":200,"message":"success","data":[...],"timestamp":...}
    }

    // 3. 返回无数据（如删除、更新接口）
    @DeleteMapping("/{id}")
    public void deleteUser(@PathVariable Long id) {
        userService.removeById(id); // 自动封装为 {"code":200,"message":"success","data":null,"timestamp":...}
    }

    // 4. 参数校验（@Valid 触发参数异常处理）
    @PostMapping("/add")
    public User addUser(@Valid @RequestBody UserAddDTO dto) {
        User user = userService.add(dto);
        return user;
    }
}
```

### 五、注意事项
1. **排除不需要统一格式的接口**：  
   如果某些接口（如第三方回调、文件下载）不需要统一格式，可在 `GlobalResponseAdvice` 的 `supports` 方法中排除，例如：
   ```java
   @Override
   public boolean supports(MethodParameter returnType, Class<? extends HttpMessageConverter<?>> converterType) {
       // 排除指定方法（如：UserController 的 download 方法）
       return !returnType.getParameterType().isAssignableFrom(ApiResponse.class)
               && !("download".equals(returnType.getMethod().getName()) 
                   && "com.yourproject.controller.UserController".equals(returnType.getDeclaringClass().getName()));
   }
   ```

2. **生产环境日志记录**：  
   全局异常处理器中，对于 `Exception` 兜底异常，需用日志框架（如 Logback、Log4j2）记录详细堆栈信息，方便排查问题，避免直接 `e.printStackTrace()`。

3. **HTTP 状态码与业务码区分**：  
   建议保持 `code`（业务码）与 HTTP 状态码一致（如 404 对应资源不存在，500 对应服务器错误），降低前端判断成本；特殊场景可自定义业务码（如 10001 代表“用户余额不足”）。

通过以上步骤，即可实现 Spring Boot 项目的全局统一返回格式，兼顾规范性和开发效率。
