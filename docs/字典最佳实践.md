# 字典功能完整方案

> React + Spring Boot + Caffeine + MyBatis-Plus + SQLite

## 0. 目标与要点

* **统一接口**：后端提供获取单个字典 / 批量版本号 / 批量获取字典的接口。
* **双端缓存**：
    * **后端**：基于 Spring Cache + Caffeine 的本地内存缓存（高性能、TTL、版本变更即时失效）。
    * **前端**：首次使用拉取 → 本地缓存（内存 + localStorage） → 定时对比版本号并增量刷新。
* **一致性策略**：后端以 `version` 字段为准；每次数据变更**自动/显式**提升版本号，并**驱动缓存失效**。
* **简单可维护**：MyBatis-Plus 无 XML（基础 CRUD 免写），SQLite 零运维。

## 1. 数据库表结构（SQLite）

```sql
-- 字典类型
CREATE TABLE IF NOT EXISTS dict_type
(
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    code         TEXT    NOT NULL UNIQUE,    -- 例如 ORDER_STATUS、GENDER
    name         TEXT    NOT NULL,           -- 展示名称
    version      TEXT    NOT NULL,           -- 例如 2025090101（日期+递增）或 UUID
    status       INTEGER NOT NULL DEFAULT 1, -- 1=启用, 0=禁用
    remark       TEXT,
    created_time DATETIME         DEFAULT CURRENT_TIMESTAMP,
    updated_time DATETIME         default CURRENT_TIMESTAMP
);

-- 字典项
CREATE TABLE IF NOT EXISTS dict_item
(
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    type_code    TEXT    NOT NULL,           -- 外键：dict_type.code
    item_key     TEXT    NOT NULL,           -- 业务代码，例如 PENDING、DONE
    item_value   TEXT    NOT NULL,           -- 展示文案，例如 待处理、已完成
    sort         INTEGER NOT NULL DEFAULT 0,
    status       INTEGER NOT NULL DEFAULT 1, -- 1=启用, 0=禁用
    remark       TEXT,
    created_time DATETIME         DEFAULT CURRENT_TIMESTAMP,
    updated_time DATETIME         default CURRENT_TIMESTAMP,
    CONSTRAINT uk_type_key UNIQUE (type_code, item_key)
);
```

> 版本号 `version` 建议使用：`yyyyMMddNN`（日期+两位序号）或 `ULID/UUID`。只要**变更字典项**就**刷新对应 type 的 version**。

### 2.6 Service（含缓存）

```java
@Service
public class DictService {
  @Resource private DictTypeMapper typeMapper;
  @Resource private DictItemMapper itemMapper;

  /** 获取单个字典（带缓存） */
  @Cacheable(cacheNames = "dict", key = "#code", unless = "#result == null")
  public DictResponse getDict(String code) {
    DictType type = typeMapper.selectOne(
        new LambdaQueryWrapper<DictType>()
            .eq(DictType::getCode, code)
            .eq(DictType::getStatus, 1));
    if (type == null) return null;

    List<DictItem> items = itemMapper.selectList(
        new LambdaQueryWrapper<DictItem>()
            .eq(DictItem::getTypeCode, code)
            .eq(DictItem::getStatus, 1)
            .orderByAsc(DictItem::getSort, DictItem::getId));

    DictResponse resp = new DictResponse();
    resp.setDictCode(code);
    resp.setVersion(type.getVersion());
    List<DictResponse.Item> list = new ArrayList<>();
    for (DictItem it : items) {
      DictResponse.Item vo = new DictResponse.Item();
      vo.key = it.getItemKey();
      vo.value = it.getItemValue();
      vo.sort = it.getSort();
      list.add(vo);
    }
    resp.setItems(list);
    return resp;
  }

  /** 批量获取版本号 */
  public Map<String, String> getVersions(Collection<String> codes) {
    if (codes == null || codes.isEmpty()) return Collections.emptyMap();
    List<DictType> types = typeMapper.selectList(
        new LambdaQueryWrapper<DictType>()
            .in(DictType::getCode, codes)
            .eq(DictType::getStatus, 1));
    Map<String, String> map = new HashMap<>();
    for (DictType t : types) map.put(t.getCode(), t.getVersion());
    return map;
  }

  /** 字典发生变更后：更新版本号并清缓存 */
  @CacheEvict(cacheNames = "dict", key = "#code")
  @Transactional
  public void bumpVersionAndEvict(String code, String newVersion) {
    DictType type = typeMapper.selectOne(
        new LambdaQueryWrapper<DictType>().eq(DictType::getCode, code));
    if (type == null) return;
    type.setVersion(newVersion);
    type.setUpdateTime(OffsetDateTime.now().toString());
    typeMapper.updateById(type);
    // CacheEvict 已清理该 code 的缓存
  }

  /** 帮助方法：生成版本号 */
  public static String nextVersion() {
    // 简单实现：yyyyMMddHHmmss
    return DateTimeFormatter.ofPattern("yyyyMMddHHmmss")
        .format(LocalDateTime.now());
  }
}
```

> **写入/编辑字典**时，务必在 service 中调用 `bumpVersionAndEvict(code, nextVersion())`，保证后端缓存与版本一致，并“通知”前端在下次版本对比时刷新本地缓存。

### 2.7 Controller（API）

```java
@RestController
@RequestMapping("/api/dict")
public class DictController {

  @Resource private DictService dictService;

  /** 获取单个字典 */
  @GetMapping("/{code}")
  public ResponseEntity<DictResponse> getDict(@PathVariable String code) {
    DictResponse resp = dictService.getDict(code);
    if (resp == null) return ResponseEntity.notFound().build();
    return ResponseEntity.ok(resp);
  }

  /** 批量获取版本号 */
  @PostMapping("/versions")
  public ResponseEntity<Map<String, String>> versions(@RequestBody List<String> codes) {
    return ResponseEntity.ok(dictService.getVersions(codes));
  }

  /** 批量获取多个字典（可选，首屏批量加载） */
  @PostMapping("/batch")
  public ResponseEntity<Map<String, DictResponse>> batch(@RequestBody List<String> codes) {
    Map<String, DictResponse> map = new HashMap<>();
    for (String code : codes) {
      DictResponse resp = dictService.getDict(code);
      if (resp != null) map.put(code, resp);
    }
    return ResponseEntity.ok(map);
  }

  /** 管理端：变更某个字典（示例：仅刷新版本号） */
  @PostMapping("/admin/refresh/{code}")
  public ResponseEntity<Void> refresh(@PathVariable String code) {
    dictService.bumpVersionAndEvict(code, DictService.nextVersion());
    return ResponseEntity.ok().build();
  }
}
```

### 3.3 字典缓存管理器（内存 + localStorage）

```ts
// store/dictCache.ts
import { fetchDict, fetchVersions } from "../api/dict";
import type { DictResponse } from "../types/dict";

type CacheEntry = { version: string; items: DictResponse["items"] };

const LS_KEY = "dictCache";

export class DictCache {
  private mem = new Map<string, CacheEntry>();

  constructor() {
    try {
      const raw = localStorage.getItem(LS_KEY);
      if (raw) {
        const obj = JSON.parse(raw) as Record<string, CacheEntry>;
        Object.entries(obj).forEach(([k, v]) => this.mem.set(k, v));
      }
    } catch {}
  }

  private persist() {
    const obj: Record<string, CacheEntry> = {};
    this.mem.forEach((v, k) => (obj[k] = v));
    localStorage.setItem(LS_KEY, JSON.stringify(obj));
  }

  async get(code: string) {
    if (this.mem.has(code)) return this.mem.get(code)!.items;
    const data = await fetchDict(code);
    this.mem.set(code, { version: data.version, items: data.items });
    this.persist();
    return data.items;
  }

  async refreshAll() {
    const codes = Array.from(this.mem.keys());
    if (codes.length === 0) return;

    const versions = await fetchVersions(codes);
    for (const code of codes) {
      const local = this.mem.get(code);
      const remoteVersion = versions[code];
      if (remoteVersion && local && remoteVersion !== local.version) {
        const data = await fetchDict(code);
        this.mem.set(code, { version: data.version, items: data.items });
      }
    }
    this.persist();
  }

  setMany(batch: Record<string, DictResponse>) {
    Object.values(batch).forEach((d) => {
      this.mem.set(d.dictCode, { version: d.version, items: d.items });
    });
    this.persist();
  }

  clear() {
    this.mem.clear();
    localStorage.removeItem(LS_KEY);
  }
}

export const dictCache = new DictCache();
```

### 3.4 Hook：组件按需获取字典

```ts
// hooks/useDict.ts
import { useEffect, useState } from "react";
import { dictCache } from "../store/dictCache";
import type { DictItem } from "../types/dict";

export function useDict(code: string) {
  const [items, setItems] = useState<DictItem[] | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let alive = true;
    (async () => {
      try {
        const data = await dictCache.get(code);
        if (alive) setItems(data);
      } finally {
        if (alive) setLoading(false);
      }
    })();
    return () => { alive = false; };
  }, [code]);

  return { items, loading };
}
```

## 4. 数据变更与版本策略（关键）

* **变更触发**：新增/修改/删除任意 `dict_item` → 必须调用 `bumpVersionAndEvict(code, nextVersion())`。
* **后端缓存**：`@Cacheable` 命中后会缓存 `DictResponse`；变更时通过 `@CacheEvict` 精确清理对应 `code`。
* **前端同步**：
    * **主动推送**：通过SSE实时接收变更通知（优先使用）
    * **降级策略**：定时调用 `/api/dict/versions` 对比版本（当SSE不可用时）

## 5. 实时通知实现（SSE）

### 5.1 后端实现

```java
// 订阅SSE事件流
@GetMapping(path = "/subscribe", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter subscribe(@RequestParam String clientId) {
    SseEmitter emitter = new SseEmitter(3600000L); // 1小时超时
    // 管理连接生命周期
    emitter.onCompletion(() -> emitters.remove(clientId));
    emitter.onTimeout(() -> emitters.remove(clientId));
    return emitter;
}

// 字典变更时通知所有客户端
public void notifyClients(String dictCode, String newVersion) {
    emitters.forEach((clientId, emitter) -> {
        try {
            emitter.send(SseEmitter.event()
                .name("dict-update")
                .data(Map.of(
                    "dictCode", dictCode,
                    "version", newVersion,
                    "timestamp": System.currentTimeMillis()
                )));
        } catch (Exception e) {
            emitters.remove(clientId);
        }
    });
}
```

### 5.2 前端实现

```ts
// 创建EventSource连接
const eventSource = new EventSource('/api/dict/subscribe?clientId=' + uniqueClientId);

// 监听字典变更事件
eventSource.addEventListener('dict-update', (e) => {
    const data = JSON.parse(e.data);
    dictCache.refresh(data.dictCode); // 刷新指定字典
});

// 错误处理
eventSource.onerror = () => {
    // 降级为定时轮询
    setInterval(() => dictCache.refreshAll(), 600000); // 10分钟
};
```

### 5.3 优势与注意事项

* **实时性**：变更后立即通知，无需等待轮询间隔
* **效率**：减少不必要的版本检查请求
* **兼容性**：自动降级为轮询机制确保可靠性
* **注意事项**：
    * 需要处理连接断开和重连
    * 生产环境建议添加认证和心跳机制
    * 考虑浏览器连接数限制
* **可选优化**：管理端“发布字典”时，后端可写一个**变更通知**（如 SSE/WebSocket/消息队列）推送到前端，前端收到后立即刷新该字典，进一步缩短一致性时延。

## 5. 测试清单（建议）

1. **首次使用加载**：页面首次进入使用 `ORDER_STATUS`，应调用后端接口一次并落入本地缓存。
2. **二次进入复用**：同一页面再次进入应直接使用本地缓存，不再打接口。
3. **定时刷新**：将后端 `ORDER_STATUS` 的 version 手动提升，等待前端定时器触发，观测前端本地缓存被刷新。
4. **后端缓存命中**：同一字典反复请求，后端日志应能看到 `@Cacheable` 命中（减少 DB 查询）。
5. **禁用字典**：`dict_type.status=0` 时接口应忽略该字典。
6. **字典项停用**：`dict_item.status=0` 项不应返回。
7. **批量接口**：`/api/dict/batch` 传入多个 code，响应结构正确。

## 6. 常见问题与处理

* **SQLite 并发**：SQLite 适合单机读多写少；写多场景建议队列化、更换 DB 或使用 WAL 模式。
* **版本生成**：用 `yyyyMMddHHmmss` 足够；如果需要严格单调递增，配合 DB 行锁或使用 ULID。
* **缓存容量**：Caffeine `maximumSize` 根据字典体量调整；大体量字典（如省市区）可以服务端分页/拆分或前端 IndexedDB 存。
* **前端离线**：缓存可离线使用；上线后首次联网会自动对比版本并刷新。
